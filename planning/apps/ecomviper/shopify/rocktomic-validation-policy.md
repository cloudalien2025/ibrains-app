# Rocktomic Validation Policy (Phase 2)

Last updated: 2026-05-31 (UTC)

## Purpose

Phase 2 formalizes offline Rocktomic package validation so platform operators can determine if SKU facts are clean enough before any database import or runtime app consumption.

This policy applies to the offline package generated by:

- `npm run ecomviper:build-rocktomic-supplier-data`

## Scope Boundary (Phase 2)

- Offline package validation only.
- No data import into `ibrains-ecommerce-prod-postgres`.
- No production schema migration.
- No runtime route/component behavior changes.
- No Product Editor / Generate Intelligence / Image Studio / OptiBay / OptiWal / Optizon package binding.
- No new sync buttons, background workers, or render-path source fetching.

## Validation Policy Version

- `rocktomic_phase2_v1`

## Field Classification

### Blocking Fields

A SKU is blocked when required blocking facts are missing.

Core blocking fields:

- `sku`
- `productName`
- `source.catalogRow`
- `pricing.record`
- `pricing.wholesaleCostOrMembership`
- `inventory.record`
- `inventory.availability`
- `assets.record`

Supplement blocking fields:

- `supplementFacts.servingSize`
- `supplementFacts.servingsPerContainer`
- `supplementFacts.activeIngredients`
- `assets.coaUrl`
- `assets.labelTemplateOrEquivalent`
- `assets.usableProductAsset`

Conditionally required supplement fields (only when source availability is detected):

- `supplementFacts.otherIngredients`
- `supplementFacts.containerSize`
- `supplementFacts.productWeight`

### Warning Fields

Warning defects do not block SKU usage but reduce quality.

Current warning fields:

- `assets.mockupUrl` (warning when label exists but mockup is missing)
- `assets.secondaryAssetLinks`
- `apparel.sizingFields` for apparel SKUs

### Not-Applicable Fields

Fields marked not-applicable do not count as missing defects.

Examples:

- supplement-fact fields on apparel SKUs
- apparel sizing fields on supplement SKUs
- conditional supplement fields not present in source text/signals

## SKU Status Contract

Each SKU emits one status:

- `usable`: no blocking defects and no warning defects
- `usable_with_warnings`: no blocking defects and one or more warning defects
- `blocked`: one or more blocking defects
- `extraction_error`: SKU cannot be validated due to source/extraction failure
- `not_applicable`: SKU is outside validation applicability

## Package Status Contract

The package emits one status:

- `pass`: no blocked SKUs, no extraction-error SKUs, no source errors above threshold
- `pass_with_warnings`: no blocked SKUs/extraction errors, but warning defects exist
- `fail`: blocked SKUs exist, extraction-error SKUs exist, or source errors exceed threshold

Current source-error fail threshold: `0`.

## Downstream Readiness Flags (Offline Only)

Each SKU includes policy-derived readiness flags in package artifacts:

- `usableForProductEditor`
- `usableForGenerateIntelligence`
- `usableForImageStudio`
- `usableForOptiBay`
- `usableForOptiWal`
- `usableForOptizon`

These are advisory package fields only in Phase 2 and are not wired into runtime app behavior.

## Output Contract

Phase 2 package outputs include:

- `data/ecomviper/suppliers/rocktomic/latest/validation-report.json`
- `data/ecomviper/suppliers/rocktomic/latest/audit.csv`

Validation report includes package status, SKU status results, blocking/warning defects, not-applicable fields, coverage summaries, source errors, and policy version.

Audit CSV includes operator-friendly validation status, defect summaries, and downstream readiness columns.
